# QQ 空间可选配图指南

这份指南面向希望让自己的 Agent 定时发布 QQ 空间说说的用户。目标是：根据文案内容决定是否配图，适合时发布文字加图片，不适合时保持纯文字。

## 适用范围

- 适用于已经拥有可用 QQ 空间登录态、OneBot/NapCat 接口和本地发布脚本的环境。
- 本指南只描述通用流程，不包含任何真实 QQ 号、群号、服务器地址、token、API Key、Cookie、私聊内容或本机绝对路径。
- 文中的 `<HERMES_HOME>`、`<PUBLISHER>`、`<IMAGE_PATH>` 和 `<IMAGE_URL>` 都是占位符，必须替换成用户自己的值。

## 推荐发布契约

Agent 每次只生成一条说说，并按以下顺序执行：

1. 读取允许使用的近期群聊或内容来源。
2. 判断文案是否适合配图。
3. 只有找到与文案直接相关、且来源合法的图片时才配图。
4. 发布前检查最近的 QQ 空间记录，避免重复主题或重复文案。
5. 发布命令只执行一次；失败后记录失败原因，不自动重试。
6. 只有收到明确成功回执后，才把文案写入去重存储。

建议把发布器设计为以下两种明确调用形式：

```bash
# 纯文字
<PUBLISHER> "<TEXT>"

# 文字加图片
<PUBLISHER> --image "<IMAGE_PATH>" "<TEXT>"
```

图片参数也可以接受受信任的短时效远程图片 URL，但必须使用严格的 HTTPS 域名白名单。不要允许 Agent 将任意 URL 直接交给图片下载器。

## 图片选择规则

适合配图的例子包括：

- 文案明确讨论某张照片、截图、插画、表情或现场画面。
- 文案总结了某条消息，而该消息带有可访问的对应图片。
- 图片与文案共享明确主题关键词，并且图片来自允许的群聊或本地媒体目录。

不适合配图的情况包括：

- 只有普通闲聊，没有对应图片。
- 图片与文案只有时间上的接近，没有主题关联。
- 图片来自私聊、未授权来源或无法确认其权限的目录。
- 图片 URL 已过期、文件不存在、格式无法识别或大小超过发布器限制。

没有合适图片时，应直接使用纯文字命令。不要为了让动态“看起来完整”而配无关图片。

## 群聊媒体来源

如果使用消息数据库，建议只读取明确属于群聊的记录，并只取必要字段：

- 群聊标识和消息时间
- 可公开使用的正文摘要
- 图片缓存路径或受限媒体 URL
- 媒体是否已经下载并通过文件检查

不要把原始消息 payload、Cookie、Authorization header、token、完整媒体查询参数或私聊正文写入日志或共享文档。图片 URL 通常有时效性，不能把数据库中的 URL 当作永久资源；需要在发布前重新检查可访问性。

## 上传与发布

带图发布通常分为两个 HTTP 步骤：

1. 调用 QQ 空间图片上传接口，取得图片元数据。
2. 将上传返回的图片标识和富媒体字段，与文字一起提交到说说发布接口。

发布器至少应检查：

- HTTP 状态码
- 上传接口的业务成功码
- 图片元数据中是否存在发布所需的图片标识
- 说说接口的业务成功码

图片上传成功不等于说说发布成功。只有第二步明确成功，才能报告整条动态成功。

## 失败与重试

为了避免重复动态，建议采用以下语义：

- 参数、文件、域名或图片大小检查失败：不发请求，直接失败。
- 图片上传失败：不调用说说发布，不重试。
- 说说发布返回明确失败：不写去重存储，不重试。
- 返回无法解析但 HTTP 状态为成功：不要自行断言业务成功；记录为“回执未确认”，交给维护者处理。
- 进程锁已被占用：跳过本次任务，不启动第二个发布流程。

如果业务确实需要重试，必须使用幂等键或先通过 QQ 空间回读确认，而不是盲目再次发布。

## 去重

去重应发生在发布前，并且至少比较最近一段时间的：

- 文案规范化结果
- 主题关键词
- 已发布图片标识或图片内容摘要

去重记录只能在发布成功后写入。查询字段要使用实际数据库 schema 中的正文列，例如 `long_term_entries.value`；不要凭字段名猜测，也不要在异常时静默把重复保护当作已通过。

## Agent 操作提示模板

可以将下面的中性规则加入自己的定时任务提示中，再替换为自己的脚本路径：

```text
先读取允许使用的群聊内容，只选择群聊，不使用私聊。
根据文案判断是否需要配图。只有存在与文案直接相关、可访问且经过允许的本地图片时，才在发布命令中加入 --image；没有合适图片就发布纯文字。
发布前检查最近的去重记录。发布器只执行一次，不重试。
只有明确成功回执后才写入去重记录；上传失败或发布失败都不要写入。
```

## 验证清单

在真实发布前，先完成不产生动态的检查：

- `--help` 能显示文字和可选图片参数。
- 纯文字 `--dry-run` 通过。
- 本地图片 `--dry-run` 通过。
- 不存在的文件会被拒绝。
- 不在白名单中的远程域名会被拒绝。
- mock HTTP 验证上传请求先于发布请求。
- mock 验证发布请求包含上传返回的图片字段。
- 上传失败和发布失败都不会写入去重存储。
- 当前运行环境的代理、Cookie 和凭据不会被写入输出。

最后只在维护者明确允许时做一次真实带图发布，并记录是否取得可确认的 QQ 空间业务回执。不要用定时任务反复试错。
